적용과 한계를 분리

보안 상태

확인된 보호

  • 공개 사이트 HTTPS 사용
  • 진단 입력은 기본적으로 브라우저 안에 저장
  • 비밀값을 증거·공유 링크에 넣지 말라는 경고 제공
  • 서비스 작업자는 같은 출처의 공개 정적 파일만 임시 저장
  • 인증·API 경로는 오프라인 저장 대상에서 제외

호스팅 한계

GitHub Pages에서는 저장소 파일만으로 응답 보안 헤더를 직접 설정할 수 없습니다.
HTTPS·HSTS는 제공자 응답에서 관찰하지만, 콘텐츠 보안 정책(CSP)과 프레임 차단 헤더는 적용됐다고 자동 통과시키지 않습니다.

현재 선택지

  1. 현 호스팅을 유지하고 한계를 공개하며 위험을 수용
  2. Cloudflare 등 중간 통로 서버를 사용해 헤더 추가
  3. 응답 헤더를 제어할 수 있는 호스팅으로 이동

호스팅 변경 전까지 CSP와 프레임 차단은 `차단` 또는 `미확인` 증거로 유지합니다.
