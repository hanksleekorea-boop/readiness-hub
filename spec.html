01제품 정의와 성공 기준

무엇을 만드는가를 한 문장으로 고정하고, 성공을 숫자로 정의한다. 이 장의 정의와 충돌하는 기능은 뒤에서 어떤 논리로도 정당화되지 않는다.

서비스가 지금 상업 출시를 해도 되는지를, 자기 신고와 기계 측정을 절대 섞지 않은 채, 업계 실측 기준선과 나란히 놓고, 시간이 지나면 낡는 증거로 판정하는 도구.

제품이 아닌 것

  • 컴플라이언스 감사 도구가 아니다 — SOC 2·ISO 인증을 대행하지 않는다. Vanta·Drata의 영역이며 우리는 그 위층(상업화 판단)에 있다.
  • 프로젝트 관리 도구가 아니다 — 할당·마감은 있으나 스프린트·번다운은 없다. Jira·Linear로 내보낸다.
  • 성능 모니터링 도구가 아니다 — Lighthouse를 부르되 APM을 대체하지 않는다.
  • 체크리스트가 아니다 — 체크리스트는 시점 스냅샷이고, 우리는 신선도를 가진 스트림이다. 이 차이가 제품의 전부다.

  • 인증 — Bearer 토큰(PAT 또는 OAuth). 토큰은 조직·범위(scope) 단위, 최소 권한 원칙.

  • 웹훅 — HMAC-SHA256 서명(X-CRH-Signature), 타임스탬프 5분 허용, 재시도 5회 지수 백오프.

08온보딩과 활성화

가치 실현까지의 시간을 3분으로 설계한다. 가상 사용자 1000명 시험에서 이 설계가 결과 획득률을 20.3%에서 72.9%로 끌어올렸다.

0:00 랜딩 — 로그인 없이 [퀵체크 시작]
0:10 방향 9문항 — 선택지 탭만, 입력 없음
1:20 게이트 3문항 — 예/부분/아니오
1:50 첫 결과 — 점수 + 업계 비교 + 차단 목록
2:00 [이어서 진단] → 계정 생성(패스키 1회 탭)
2:20 ⓪ 3분 최소 8항목 — 가장 자주 막는 게이트
3:00 상용화 지수 + 갭 순위 + 다음 할 일 3개

설계 규칙

  • 로그인 벽을 결과 앞에 두지 않는다 — 첫 점수는 비로그인으로 본다. 가입은 '저장하려면'의 이유로만 요구한다.
  • 재입력 금지 (WCAG 3.3.7) — 퀵체크 응답은 그대로 방향 프로파일·가중치·목표 레벨로 승계된다. 다시 묻지 않는다.
  • 빈 화면을 만들지 않는다 — 서비스가 없으면 샘플 3종으로 즉시 체험. 항목이 없으면 범위 넓히기 버튼.
  • 다음 행동은 항상 하나 — 모든 화면에 '지금 딱 하나만 한다면' 이 있다.
  • 투어는 3단계 이하, 건너뛰기 가능, 재실행 가능.

활성화 정의

가입 후 7일 내 첫 게이트 판정 도달을 활성화로 본다(목표 60%). 점수를 본 것이 아니라 출시 가부 판정을 본 시점이 가치 실현이다.

09진단 엔진

점수는 계산 결과가 아니라 신선도를 가진 증거들의 현재 상태 집계다. 이 장의 산식은 전부 공개하며 계산기를 제공한다.

산식

항목 기여 = 항목가중치(게이트 2 / 일반 1) × 점수(0~4) × 신선도계수
영역 점수 = Σ(항목 기여) ÷ Σ(항목가중치 × 4) × 100
종합 = Σ(영역가중치 × 영역점수) ÷ Σ(영역가중치)
상용화 지수 = Σ(축가중치 × 축점수) ÷ Σ(활성 축가중치) [1축 50 : 2축 25 : 3축 25]

17조직 관리와 신뢰 센터

관리자가 조직 전체를 한 화면에서 보고, 외부에는 우리가 고른 것만 보인다.

조직 대시보드

  • 서비스 카드 격자 — 상용화 지수 · 게이트 차단 수 · 신선도 · 마지막 갱신 · 담당자
  • 위험 서비스 경보 — 게이트 차단 발생, 점수 급락, 증거 만료 20% 초과 중 하나라도 걸리면 상단 고정
  • 신선도 히트맵 — 서비스 × 영역 격자. 붉을수록 오래된 증거. 조직 전체의 노후화를 한눈에
  • 추세 — 조직 평균 지수의 12주 이동. 목표선 표시

신뢰 센터 (공개 페이지)

  • 고객·파트너에게 보여줄 항목만 골라 공개. 항목별로 '공개/비공개' 토글
  • 구성 — 준비도 요약, 보유 인증, 상태 페이지 링크, 보안 문의 창구, 마지막 갱신일
  • 마지막 갱신일을 반드시 크게 표시 — 신뢰 센터가 낡으면 없느니만 못하다
  • 공개 항목이 만료되면 자동으로 '갱신 중'으로 표시되고 값은 가려진다

  • 렌즈 지연 로드 — 107개 기준 데이터는 진단 화면 진입 시에만. 랜딩·퀵체크는 필요 항목만.
  • 차트 자체 구현 — 차트 라이브러리 미사용. SVG 직접 생성으로 수십 KB 절감.
  • QR 자체 구현 — 외부 의존 0, 12KB.
  • 스켈레톤 높이 고정 — CLS 0 을 구조적으로 보장.
  • 점수 재계산 메모이제이션 — 변경된 영역만 재계산해 16ms 유지.

23국제화

한국어·영어를 1급으로, 나머지는 확장 가능하게. 번역은 문자열 교체가 아니라 기준 자체의 현지화다.

  • 2언어 1급 — 한국어·영어. UI 문자열 + 107개 기준 전문 + 루브릭 + 도움말 전부.
  • 기준의 현지화 — 법규 항목은 언어가 아니라 관할에 따라 달라진다. 한국(전자상거래법·개인정보보호법) / EU(GDPR·EAA) / 미국(주별) 렌즈 변형을 별도 제공.
  • 서식 — 날짜·숫자·통화는 Intl 로. 사용자 시간대 기준으로 만료일 계산(자정 경계 오차 방지).
  • 레이아웃 — 한국어는 영어 대비 텍스트가 짧고 줄바꿈 규칙이 다르다. 버튼 최소 너비를 글자 수가 아닌 px 로 고정.
  • RTL 대비 — 논리 속성(margin-inline-start)만 사용. 지금 언어는 없지만 나중에 비용이 0이 되게.
  • 번역 누락 — 키가 없으면 영어로 폴백하고 개발 모드에서 경고. 빈 문자열을 절대 표시하지 않는다.

24모바일 특화

모바일은 PC의 축소판이 아니다. 진단은 이동 중에 짬으로 하는 일이라는 전제로 설계한다.

  • 기본 범위 ⓪ 3분 최소 — 모바일에서 107개를 요구하지 않는다. 페르소나 시험에서 모바일 완주율이 이 설계로 19.2%→72.9%가 됐다.
  • 터치 타깃 48dp — WCAG 24px 하한이 아니라 Android 권장 48dp + 간격 8dp 를 기준으로.
  • 점수 입력 5버튼 격자 — 한 손 엄지 도달 범위 고려, 하단 배치.
  • 하단 이동줄 5탭 — 퀵체크 · 진단 · 대시보드 · 갭 · 더보기. safe-area-inset-bottom 반영.
  • 고정 잠정 결과 — 상단 sticky. 스크롤 중에도 현재 점수가 보인다.
  • 홈 화면 설치(PWA) — manifest + 서비스워커. standalone 실행, 아이콘 192/512/maskable.
  • 오프라인 — 앱 껍데기 캐시 + 입력 로컬 대기열. 비행기 모드에서도 채점 가능, 복귀 시 자동 동기화.
  • 푸시 — 게이트 차단·멘션만. 나머지는 인앱으로.
  • 실기기 검증 필수 — 홈 설치 안내·터치 정확도·노치/제스처 바 간섭·오프라인 4종은 에뮬레이터로 대체 불가.
