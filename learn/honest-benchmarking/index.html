안내서 3 · 시장 비교

유명한 서비스가 아니라 실제로 비슷한 서비스를 비교합니다.

교육 앱을 대형 쇼핑몰과 비교하거나 작은 도구를 글로벌 협업 플랫폼과 비교하면 숫자는 화려해도 행동으로 이어지지 않습니다. 좋은 비교는 같은 사용자의 같은 문제를 해결하는 서비스부터 고릅니다.

갱신일 2026-08-31 · 내장 500개 도메인은 후보 검색용

1. 대상 서비스를 한 문장으로 고정합니다

“누가, 어떤 문제를, 어떤 핵심 행동으로 해결하고, 무엇을 결과로 받는가”를 씁니다. 플랫폼, 수익 방식, 시장, 출시 단계도 확인 가능한 범위에서만 기록합니다. 문서와 실제 화면이 다르면 실제 동작을 우선하고 차이를 남깁니다.

2. 주 도메인 하나와 보조 도메인을 고릅니다

Readiness Hub의 500개 도메인 카탈로그는 이름을 찾는 사전입니다. 카탈로그 번호가 경쟁사를 증명하지는 않습니다. 기능·사용자·수익 방식·플랫폼의 겹침을 보고 주 도메인 하나와 보조 도메인 최대 두 개를 후보로 정합니다.

3. 비교 대상을 선정한 이유를 남깁니다

차원질문좋은 근거
사용자같은 사람이 같은 상황에서 선택하는가?공식 제품 설명·도움말
문제해결하려는 핵심 문제가 겹치는가?실제 온보딩·기능 문서
핵심 행동입력→처리→결과 흐름이 비슷한가?공개 화면·공식 시연
수익 방식무료·광고·구독·거래 중 무엇인가?공식 가격·정책
시장국가·규모·출시 단계가 비교 가능한가?공식 회사·스토어 자료

4. 기능 이름이 아니라 성공 조건을 비교합니다

예를 들어 “대시보드가 있다”는 사실만으로는 부족합니다. 처음 온 사용자가 현재 상태를 이해하는 시간, 부족한 점을 행동으로 바꾸는 흐름, 근거의 최신성, 결과를 공유하는 방법처럼 사용자 결과를 비교해야 합니다. 각 기능에서 가장 좋은 관행을 찾고, 서로 충돌하지 않는 요소만 합쳐 이상 기준을 만듭니다.

5. 같은 척도와 같은 날짜를 사용합니다

우리 제품은 실제 성능 수치인데 경쟁사는 홍보 문구만 있다면 같은 표의 점수로 만들지 않습니다. 비교 대상마다 출처, 관찰일, 적용 플랫폼, 확인하지 못한 값을 남깁니다. 최소 세 개의 검증된 비교 대상이 없으면 백분위와 순위는 계산하지 않고 조사해야 할 자료를 갭으로 제시합니다.

계산 불가는 실패가 아닙니다. 근거가 없는데 정밀한 숫자를 만드는 것보다, 무엇을 더 확인해야 하는지 알려 주는 편이 의사결정에 안전합니다.

6. 결과를 개선 작업으로 바꿉니다

  1. 우리의 강점과 부족한 점을 기능별로 적습니다.
  2. 사용자 영향, 구현 난이도, 검증 가능성으로 정렬합니다.
  3. 무엇을 바꿀지와 기대 효과를 한 문장으로 씁니다.
  4. 완료를 확인할 같은 조건의 시험을 정합니다.
  5. 경쟁사 복제가 아니라 우리 서비스 방향에 맞는지 다시 확인합니다.
